# Как сравнить оригинал и две новые версии

## Предложение

A — действующий 3d-arena.ru; B — Select; C — Social. Сравнивать целые страницы, сохранив одинаковые предложения, тарифы, объявления, аудиторию, географию и расписание. Это тест подачи продукта, а не отдельной кнопки.

Три обычные конкурирующие кампании сами по себе не дают чистого сравнения: различаться могут аудитории, обучение и распределение показов. Для запуска использовать штатный эксперимент Директа либо согласованное случайное распределение на одном домене с закреплением версии за посетителем. Реальный запуск не выполнялся.

Предпочтительно разместить B и C на том же домене отдельными маршрутами. GitHub Pages сейчас нужны для просмотра: отдельный хост, скорость доступа и доверие к адресу могут искажать эффект дизайна. Сохранить мобильные/настольные и брендовые/небрендовые срезы.

## До расходования бюджета

1. Сверить цены, акцию «ночь 800 ₽», возрастные ограничения, конфигурации, PS5 и правила бонусов с клубом/LANGAME на дату старта.
2. Определить единую цель `paid_booking` или `completed_visit` в связке с системой бронирования. Проверить цепочку на тестовом заказе с разрешения владельца. Не создавать фиктивные заказы ради отчёта.
3. Если LANGAME не отдаёт подтверждение оплаты с вариантом/клиентом, запускать только исследование верхней части воронки. `langame_booking` — клик, `booking_call` — клик по телефону, `booking_telegram` — переход, не лид и не продажа.
4. Подключить согласованный счётчик через config.js, проверить события в отладке Метрики, одинаковое измерение на A/B/C, фильтрацию команды/ботов. Сейчас `metrikaId: null`: внешние счётчики в демо не отправляют данные.
5. Проверить, что `arena_variant=B/C` и рекламные параметры реально доступны после перехода в LANGAME. Передача параметра в URL реализована; сохранение внешним сервисом и связь с заказом не подтверждены.
6. Задать бюджетный предел, текущую базовую конверсию и минимальное полезное улучшение. Без этих данных бюджет и требуемую выборку не назначать.

## Дизайн эксперимента

- Доли примерно равные: 34/33/33; кампании и бюджеты пропорциональны долям. Один человек не должен попадать в разные варианты без необходимости.
- Главная метрика после подтверждения интеграции: оплаченные брони на уникального участника; затем стоимость состоявшегося визита и выручка на участника.
- Дополнительные: клики LANGAME, звонки, Telegram, подбор тарифа. Они объясняют путь, но не определяют экономического победителя.
- Защитные: отмены, неявки, средний чек, проданные часы, доступность мест, доля ошибок на телефонах.
- Срок считать после настройки измерения и учёта обучения кампаний. Смотреть полные недели, одинаковые дни/часы, не останавливать при первом удачном всплеске.
- Яндекс рекомендует равные условия, учитывать обучение, накопить данные и оценивать минимум два полных бюджетных интервала. Рекомендация по минимуму конверсий не заменяет расчёт статистической мощности.
- До запуска: выбрать уровень ошибки (например 5%), мощность (например 80%), минимальный эффект и пересчитать размер выборки с поправкой на два сравнения B/A и C/A. Это предлагаемые параметры дизайна, не уже рассчитанный тест.
- При недостаточном потоке сначала A/B, затем победитель/C. Если интервал оценки остаётся широким, результат «не определён», а не «дизайны одинаковы».
- Условие досрочной остановки: сломанное бронирование, неверные цены, потеря меток или достижение согласованного лимита расхода. Для статистического раннего завершения нужен заранее выбранный последовательный метод.

## События, уже подготовленные в обеих версиях

| Событие | Значение |
|---|---|
| variant_view | Открыта версия; вариант B/C |
| price_selection | Изменён день, зал или пакет |
| langame_booking | Клик по переходу в LANGAME, с местом кнопки |
| booking_call | Клик по телефону администратора |
| booking_telegram | Переход в Telegram |
| route_click | Переход к карте |
| reviews_click | Переход к отзывам |

События помещаются в `window.dataLayer`. При включении `metrikaId` также вызывается `ym(..., 'reachGoal', ...)`. Для этих целей требуется соответствующая настройка в Метрике. Новая рекламная ссылка заменяет старый набор меток; прямой повторный визит наследует последний набор не дольше 30 дней. Это выбранная модель последнего рекламного перехода, не доказательство платформенной атрибуции.
